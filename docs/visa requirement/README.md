# 유학비자 발급조건 룰셋

베트남 국적 중심의 한국 유학비자(D-2 / D-4) 발급요건 룰 엔진과 판정기. 어드민 통합을 전제로 한 프로토타입.

조항 **96건** · 입력 축 **13개** + 파생 축 **1개** · 검증항목 **27건**
그중 확정되지 않은 조항 **10건** — 확정 안내로 쓰면 안 됩니다.

---

## 읽는 순서

| 순서 | 파일 | 내용 |
|---|---|---|
| 1 | **`REQUIREMENTS.md`** | **실제 발급요건 전문.** 요건 내용을 알고 싶으면 여기부터 |
| 2 | `SPEC.md` | 데이터 모델·엔진 계약·확장 방법 |
| 3 | `VERIFY.md` | 최신성 검증 절차 |

## 파일 역할

| 파일 | 역할 | 수정 |
|---|---|---|
| `rules.json` | **단일 진실원본.** 축·출처·조항·검증항목 전부 | ✅ 여기만 |
| `REQUIREMENTS.md` | 요건 전문 (자동 생성) | ❌ 생성물 |
| `README.md` | 이 문서 (자동 생성) | ❌ 생성물 |
| `index.html` | 판정기 UI (자동 생성, 단일 파일) | ❌ 생성물 |
| `index.template.html` | UI 템플릿 + 엔진 | UI 변경 시 |
| `build.py` | 생성물 3종 빌드 | 거의 안 고침 |
| `test_rules.py` | 회귀 10케이스 + 무결성 + 커버리지 | 조항 추가 시 |
| `verify.py` | 최신성 검증 훅 | 거의 안 고침 |
| `SPEC.md` / `VERIFY.md` | 스펙 / 런북 | 절차 변경 시 |

## 실행

```bash
python3 build.py        # rules.json → index.html + REQUIREMENTS.md + README.md
python3 test_rules.py   # 회귀 테스트
python3 verify.py       # 최신성 점검 (critical 미해결 시 exit 1)
```

`index.html`은 단일 파일이라 `file://`로 바로 열립니다.

## 설계 원칙

> 모든 값은 확신도와 출처를 달고 다닌다. **미확인은 면제로 폴백하지 않는다.**

공관 안내문은 규정의 전체 집합이 아니라 그 공관 신청자 분포에 맞춘 부분집합입니다. "안내문에 없음"을 "요건 없음"으로 매핑하는 순간 이 프로젝트는 실패합니다. 자세한 배경은 `SPEC.md` §0.
